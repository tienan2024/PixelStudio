# 房间与物品

最后更新：2026-10-02

当前地图按工作室、会议室、休闲厅、卧室顺序拼接，每间宽 560px，总宽 2240px。房间背景负责建筑，家具、Codex/Kimi 常驻伙伴、小猫橘子和照护物品、悬停提示分别绘制。伙伴是固定的展示角色，数据不可用时保留形象并明确显示未知；不再复制历史子代理为人物。橘子是唯一的小猫，原 `lounge-cat`、`bedroom-cat` 静态摆件已移除。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `pixel_world.py` | 组合场景、计算地图宽度、控制视口、合并绘制、房间导航与点击分发 |
| `scene_canvas.py` | 保留动态 Canvas 图元，复用坐标与选项，隐藏未使用尾部，恢复图层顺序 |
| `scene_layout.py` | 从 `assets/rooms/world.json` 读取房间顺序，累加房间偏移并检查物品 ID 重复 |
| `scene_assets.py` | 缓存建筑 PNG、裁切家具图集、整数采样；素材读取失败时提供回退入口 |
| `scene_objects.py` | 每个物品的精灵、透明像素命中、互动效果与高亮 |
| `scene_state.py` | 每个物品的状态索引、瞬时效果计时和独立存档 |
| `scene_actors.py` | 固定伙伴身份、连续路径、入座起立、散步、交替发言与选中；造型复用 `character_sprites.py` |
| `scene_pet.py` | 橘子精灵、独立照护物品、步行与照护流程、模型调用时机和小面板 |
| `pet_state.py` | 饱腹、饮水、精力、亲近值，完成照护的记录与需求存档 |
| `pet_brain.py` | 回环网关真实模型请求、字段校验、调用限额、暂停与决定存档 |
| `scene_meeting.py` | 随会议阶段叠加白板笔迹、对话气泡、倾听与蒸汽效果 |
| `companion_sources.py` | Codex 最新主任务轮次与 Kimi 网关调用的只读快照 |

`PixelWorld.WIDTH = 1120` 是展开视口的宽度上限，`HEIGHT = 224` 是固定高度；`map_width` 是配置中各房间 `width` 的总和。添加房间增加地图长度，不要求增加窗口宽度。收起视口宽 294px，额度和状态栏宽 320px；展开仍受屏幕可用宽度限制。

## 坐标、绘制与命中

- 房间 `x` 偏移由前面各房间的宽度累加，当前为 0、560、1120、1680。物品 `x` 使用房间局部坐标，绘制时加房间偏移。
- `y` 使用整幅画卷坐标：顶栏为 0–24，场景为 24–200，底部提示为 200–224。物品 `(x, y)` 锚在精灵脚底中央（`anchor="s"`），`arrival` 也是房间局部横坐标。
- `size: [width, height]` 是精灵采样的目标上限。程序按整数倍缩小裁切帧、保持比例，不强行拉伸到精确尺寸，也不放大小图。实际显示尺寸用于命中范围。
- 背景经过整数采样和纵向裁切，置于建筑层。当前 shell 原图为 2172×724，工作室和休闲厅的固定墙灯及所有窗户属于背景，不具有家具开关状态。
- 家具按 `layer` 从小到大绘制，每件家具的效果紧跟其精灵；同层保持配置顺序。地毯为 0、普通家具为 20、桌面物品为 25、座椅为 28；入座角色在会议桌等 `layer>=40` 前景之后，脚底 y>=180 的过道角色提升到前景上方。随后绘制橘子与照护物品、会议效果，最后绘制高亮与界面覆盖层。
- 家具、伙伴、橘子及照护物品命中先检查实际边界，再检查精灵透明像素；完全透明处继续查找后方物品。小猫面板优先接收点击，然后检查橘子与照护物品，再按过道角色、前景家具、入座角色、后景家具检查；伙伴与橘子头顶姓名条也可选中。

## JSON 配置

`assets/rooms/world.json` 的 `rooms` 为按显示顺序排列的房间文件名，`status_rooms` 将成员状态映射到房间 ID。当前 `version` 为 1。

| 成员状态 | 当前目标房间 |
| --- | --- |
| `active` | `studio` |
| `idle` | `lounge` |
| `systemError`、`notLoaded`、`unknown` | `studio` |

`status_rooms` 必须包含上述五个键，值必须指向已加载的房间 ID。未知上游状态统一按 `unknown` 处理。固定绘制 Codex 和 Kimi 两个伙伴，形象不代表实际子代理数。会议期间位置覆盖为 `meeting` 房间；未知保留问号，异常保留感叹号，会议及家具效果均不改变源状态。当前布局需要保留 meeting 房间及足够的伙伴站位空间。

每个房间文件使用以下字段：

| 字段 | 类型与含义 |
| --- | --- |
| `id`、`label` | 字符串；稳定的房间 ID、界面名称 |
| `width` | 正整数；房间宽度，当前统一为 560 |
| `arrival` | 整数；成员落点附近的局部横坐标，省略时为 280 |
| `background` | `assets/rooms/` 内的背景 PNG 文件名 |
| `objects` | 物品数组，允许为空 |

每件物品使用以下字段：

| 字段 | 类型与含义 |
| --- | --- |
| `id`、`label` | 字符串；全地图唯一且稳定的物品 ID、显示名称 |
| `asset` | `furniture-atlas.json` 中的素材键 |
| `x`、`y` | 数值；房间局部横坐标、画卷纵坐标，锚点为脚底中央 |
| `size` | 两个正整数；期望显示宽高上限 |
| `layer` | 数值；家具绘制顺序，默认 20 |
| `interaction` | `toggle`、`cycle`、`pulse` 或 `inspect`，默认 `inspect` |
| `states` | 非空字符串数组；状态文本与索引顺序 |
| `default` | 整数；默认状态索引，省略或无效时为 0 |
| `effect` | 可选字符串；对应 `SceneObject.animate()` 的效果分支 |
| `duration` | 有限非负秒数；`pulse` 持续时间，默认 5 |
| `description` | `inspect` 展示的说明文字，省略时使用状态文本 |

当前效果包括 `monitor`、`server`、`coffee`、`water`、`aquarium`、`arcade`、`lamp`、`wardrobe`、`bed`、`cat`、`sofa`、`books`；`bookcase` 未写 `effect` 时默认使用 `books`。效果主要按状态索引绘制，修改 `states` 的顺序时必须一并检查对应效果。

会议由任务状态自动触发；白板与会议桌均为 `inspect`，不提供手动召集或结束动作。画卷以约 33ms 心跳推进人物、镜头与收放动画，家具使用单调时钟换算出的 280ms 整数逻辑帧，避免整体提速；脉冲效果仍按真实秒数结束。

`furniture-atlas.json` 的条目可以是主图集中的 `[x1, y1, x2, y2]`，或 `{"image":"meeting-furniture.png","rect":[x1,y1,x2,y2]}` 指向独立图集；右下界不包含在帧内。当前有 25 个素材键，包含 6 个指向 `cat-care.png` 的照护物品键；旧 `cat` 素材保留兼容，但不再摆放。普通家具实例必须有独立 `id`。

橘子及其物品由 `PetLayer` 独立管理。`assets/cat-corner.json` 的 `objects` 指定休闲厅的粮碗、水碗、毛线球与卧室的猫窝；这些物品的空满状态来自需求值，不使用普通家具的 `toggle` / `cycle` 存档。配置、动作与模型接口详见 [03-小猫与模型照护](03-小猫与模型照护.md)。

## 操作与存档

展开后可点击房间按钮；画面获得焦点时，`1` / `2` / `3` / `4` 选择对应房间，`←` / `→` 循环切换。滚轮每步横向平移 96px。悬停显示物品说明，点击触发交互，选中物品后 `Enter` 可再次触发；两侧卷轴收起画卷。会议规则详见 [02-常驻伙伴与总结会议](02-常驻伙伴与总结会议.md)。

没有单独寻找小猫的按钮或快捷键；直接点击橘子、粮碗、水碗、毛线球或猫窝打开面板；点击前三件照护物品还会向模型提出对应意图。宠物需求与模型调用各有独立存档，不计入下表的家具交互。

| 交互 | 行为 | 是否保存 |
| --- | --- | --- |
| `toggle` | 在默认状态和其下一个状态间切换，适合两态开关 | 是 |
| `cycle` | 按数组顺序循环全部状态 | 是 |
| `pulse` | 临时进入索引 1，到期返回默认值；再次触发重置到期时间 | 否 |
| `inspect` | 只显示说明 | 否 |

脉冲物品应至少提供两个状态并以索引 0 为静止默认值。例如咖啡机冲煮 6 秒、绿植浇水 4 秒、床显示晚安效果 7 秒；场景心跳使用单调时钟收回效果。

家具存档位于项目上级目录 `.runtime/widget-world-state.json`，与窗口偏好和团队统计分开：

```json
{"version": 1, "objects": {"bedroom-lamp": 1, "monitor-a": 2}}
```

只保存 `toggle` / `cycle` 的索引，通过临时文件替换写入。不存在、损坏或版本不匹配的存档使用配置默认值；未知 ID、越界索引和非整数值被忽略。稳定 ID 用来关联旧存档，重命名 ID 会使旧记录不再生效；调整状态顺序会改变已有索引的含义。写入失败不阻止场景继续运行。

`PixelWorld` 默认使用 `pet_live=False`，便于仅用内存状态预览小猫，不访问模型、不读写宠物存档。桌面入口 `widget.py` 显式启用 `pet_live=True`。预览的外观不证明真实模型调用或照护已完成。

## 添加房间或物品

1. 在 `assets/rooms/` 放入房间建筑 PNG 和提示词，保留原图。复制一个房间 JSON，设置唯一 `id`、名称、宽度、背景、合理的 `arrival` 与 `objects`；把文件名加入 `world.json` 的 `rooms`。需要改变成员去向时再更新完整的 `status_rooms` 映射。
2. 添加物品时优先复用图集中的素材键，在目标房间 `objects` 中填写唯一 ID、脚底坐标、尺寸、图层和交互。桌面设备与桌子、台灯与床头柜分别配置；透明区域和图层共同决定点击目标。
3. 新增素材时保留透明原图、更新图集裁切矩形及署名。使用新的 `effect` 名称时，在 `scene_objects.py` 增加对应绘制分支；仅添加名称不会自动产生新动画。
4. 重启组件读取新的房间配置，并同步本说明与素材署名。按钮间距会按视口调整，底栏显示房间总数；继续增加房间仍需检查窄视口的最小可点宽度。房间宽度需给伙伴落点和家具留出空间。

背景或家具 PNG 读取失败可回退为简易图形；房间目录或 JSON 结构错误不会自动修复。配置前检查字段与 ID，避免将素材回退误认为配置校验。

## 日常导航补充

工作室以环境和房间为中心，不设置特定成员的快捷入口。`Esc` 先关闭宠物面板，再收起画卷；面板打开时 `Enter` 不收起画卷。手动点击、房间导航或滚轮会停止当前镜头动画，并保护镜头 45 秒。宠物面板打开期间自动会议也不切走镜头。

## 渲染与收放

`widget.py` 使用同一个约 33ms 场景时钟推进收放进度和人物模拟。详情区可见时提前预留完整透明窗口和 Canvas 表面，动画期间保持它们及窄栏的屏幕位置和尺寸，仅改变逻辑视口与两侧遮罩。画卷收起时继续保留透明表面；折叠整个详情区才缩回窄窗口并隐藏画布。遮罩在主栏范围使用主栏底色、主栏之外使用透明色，避免打穿主栏边距。相同的窗口几何、场景布局不会重复提交。卡片高度变化用 `after_idle` 合并测量，不在刷新中调用嵌套 `update_idletasks()`；用户折叠操作在布局完成后保存偏好，包含底部吸附后的最终位置。

`PixelWorld._live()` 只申请一次 idle 绘制；尺寸提交、输入、心跳与镜头变化共用 `_paint_frame()`，按已提交的物理表面尺寸限制逻辑视口，再居中并更新命中区域。`set_viewport()` 保留原参数，新增可选 `offset`、`surface_width`、`panel_mask` 供桌面收放使用；点击与导航按逻辑视口转换坐标。隐藏画布也会提前准备收起遮罩，避免重开时先露出整张地图。`SceneCanvas` 复用 `actors`、`pet`、`overlay`、`hover`、`meeting_fx` 和 `effect:*` 图元；未变化的坐标、图片和文字不发送更新，未使用的尾部隐藏。图元类型变化可替换，隐藏图元恢复时重建绘制顺序；图层只在结构、恢复顺序或前后景角色变化时重排。背景和普通家具继续使用初始化图元与已有素材缓存。关闭画卷模块时取消尚未执行的 idle 绘制。

伙伴及小猫默认不显示姓名牌；选中伙伴或短暂打招呼时显示其牌，选中小猫时显示它的牌。隐藏的牌不保留命中区域。任务状态仍由下方常驻卡片展示；宽画卷的顶栏显示本地时间与时段，不表示建筑素材已切换昼夜光照。
