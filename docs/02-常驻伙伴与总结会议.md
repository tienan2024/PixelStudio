# 常驻伙伴与总结会议

最后更新：2026-10-04

## 身份与数据边界

画面中的两个角色是固定的 Codex / Kimi 伙伴，分别绑定 `companion:codex` 和 `companion:kimi`。保留银紫短发、栗色马尾造型与待机动画，不再绑定历史子代理 ID；角色常驻不表示有两个实际子代理正在执行。成员卡展示任务或模型调用状态。额度与团队小记仍使用原数据来源。

两位伙伴还有独立的生活需求与实际记忆：Codex 初始安静细致、喜欢书与绿植，Kimi 外向好奇、喜欢咖啡、聊天和橘子。真实 `k3-256k` 联合生成两人的心情、第一人称心思与日常意图；Codex 角色的名字不表示生活功能调用了 GPT。生活计划与下方真实任务状态分开，只有明确空闲的伙伴可开始自主活动。人格、请求边界和面板详见 [05-伙伴人格与日常](05-伙伴人格与日常.md)。

`companion_sources.py` 在独立后台线程读取状态；每次完成采样后约 2 秒再采样。`snapshot_with_tasks()` 让伙伴与任务记录共用一次 Codex 元数据读取；原 `snapshot()` 接口仍返回两位伙伴。额度与后台线程快照仍每 20 秒更新，快照用于状态回退与团队统计。读取失败显示未知；界面超过 15 秒没有收到新快照也会清除忙碌显示与任务记录中的旧状态。Tk 主线程只接收队列结果。

## Codex 伙伴

- 只读 `$CODEX_HOME`（默认 `~/.codex`）下最高数字版本 `state_N.sqlite` 与 `thread_history_N.sqlite`，短连接 `mode=ro`，不写库，不使用忽略 WAL 的 immutable 模式。
- 读取主线程名称、模型、项目路径、更新时间以及每个线程**最新一轮**的状态和时间；排除子代理，存在 `archived` 列时排除已归档记录。最多取近期 32 个主线程，不能把历史遗留的 inProgress 当作当前一轮。
- 最新轮次 inProgress 且有 15 分钟内活动时显示执行中；多个运行任务选择最近活动的任务并注明数量。过旧的 inProgress 标为状态待确认，不能自动宣称已完成。
- completed / interrupted / failed 分别显示最近完成、中止和失败。未加载或源不可用显示未知。SQLite 不兼容时回退 app-server 线程列表，只有明确的 active 才算运行；列表读取失败或距上次成功读取超过 60 秒时停止使用旧列表。
- 任务标题来自线程名称；它代表最近活动的任务，不代表用户当前前台选中的聊天。读取的是本地内部投影，Codex 升级改变表结构时可能降级。
- 仅取最终答复的 `phase` 元数据，不读取用户消息、工具正文、认证文件或模型输出文本。运行中的 final_answer 阶段用于触发总结会。

## Kimi 伙伴

默认读取 `http://127.0.0.1:15723/activity`；可用 `PIXELSTUDIO_GATEWAY_URL` 修改回环网关根地址。只允许 HTTP 回环主机，不发认证头，不使用环境代理，拒绝远程重定向，单次请求超时 1.5 秒、响应上限 128 KiB。

接口要求 `service=codex-model-gateway`、`schema_version=1`、`observed_at` Unix 秒以及 `active` / `recent` 数组；只接受 `route=kimi` 且模型为 kimi-for-coding / k3 / k3-256k 的记录。调用中显示模型、阶段、耗时与并发数；无调用显示空闲与最近传输结果。近期 60 秒内失败显示异常，快照超过 15 秒显示过期。404 显示未接入，连接失败显示网关离线。

网关扩展位于本机多模型路由项目的 `router/kimi_bridge.py` 和 `router/activity_status.py`；它是可选的数据源，不是 PixelStudio 内置服务。旧网关需要在空闲时重载才能提供 `/activity`。Kimi Code 配额读取和模型调用状态互相独立。HTTP 传输结束不能当作整个任务完成；网关没有活动也可能是代理在执行本机工具。

## 总结会议

会议室是四个独立房间之一，排列在工作室之后；总地图宽 2240px，视口仍最多 1120×224px。会议桌、两把椅子、白板均为独立物品。桌子为 40 层前景，角色在桌子后入座；走到过道的角色显示在前景上方，点击按可见图层做透明像素命中。

- Codex 进入最终答复阶段，或组件观察到同一轮从执行中变成刚完成，自动召集两位伙伴。结束信号后保留约 35 秒，再回到正常活动区域；新任务开始可提前结束自动会议。
- 自动会议不会在组件启动时重放旧的完成记录，也不会由每次 Kimi 传输结束触发。缺少阶段信号时不猜测“正在总结”。
- 会议完全由以上任务信号触发；界面没有手动开会按钮，白板和长桌点击只展示说明。
- 自动到期或新任务提前结束会议时，伙伴起身、经过过道返回活动位置；仅当会议自动接管的镜头仍在会议室、且伙伴与宠物面板均关闭时，等待约 1.3 秒后平滑回到工作室。手动导航会撤销自动镜头所有权。
- 总结会只控制角色的场景位置，不改变真实任务、模型或运行状态；下方卡片始终保留原始状态。
- 顶部四个房间按钮、`1–4` 或方向键切换，滚轮横向浏览。自动集合时，已展开的画卷仅在伙伴与宠物面板均关闭、且最近 45 秒没有手动操作镜头时定位会议室；画卷折叠时不主动撑开窗口。

会议不写入家具存档，重启后恢复正常活动；家具开关等持久化行为保持原样。

## 伙伴照顾橘子

小猫的真实模型决定可以指定 Codex 或 Kimi 去喂粮、添水、陪玩或摸摸。`ActorLayer.begin_care(key, x, y, action)` 为一位伙伴安排临时步行路线；`care_ready()` 仅报告是否到位，由 `PetLayer` 计时并应用照护结果；`end_care()` 按伙伴最新的真实状态安排返程。喂粮、添水、摸摸到位后持续约 3.5 秒，陪玩约 5 秒，成功完成后才更新需求值并记录。

伙伴自己的生活决定也可以提出 `care_cat` 意图，经 `PetLayer.offer_care()` 接纳后沿用同一照护执行器，标记 `source=companion-model`，不冒充橘子自己的新心愿。橘子暂停思考、有待处理意图、模型忙碌或已有照护时不接纳。两种来源的成功照护均在实际完成后留下伙伴小记与照护偏好计数；模型提出或伙伴赶来不会产生完成记录。

会议优先于照护。会议期间不发起新的宠物模型请求，伙伴先去参加会议，未过期的安排在散会后重新排队、到位并重新计时；未完成照护从模型决定被接纳起最多保留 180 秒，会议期间过期也会丢弃。暂停模型决策会撤销未完成照护。折叠详情等原因造成的长心跳间隔不会直接算作完成了照护动作。照护路线、伸手动作、猫粮和水滴等表现不改变源任务状态，下方伙伴卡仍展示真实任务或调用状态。

宠物决策与伙伴生活决策均使用 Kimi 网关，因此这些真实请求也可能显示在 Kimi 伙伴的调用状态中；这不能当作 Codex 任务完成或自动总结会的触发信号。小猫模型每小时最多 6 次，伙伴联合生活模型独立限制为 4 次。照护规则见 [03-小猫与模型照护](03-小猫与模型照护.md)，生活规则见 [05-伙伴人格与日常](05-伙伴人格与日常.md)。

## 动画与素材

- `characters-idle.png` 保留两套四帧待机动作；`characters-motion.png` 是以原角色为参考生成的 1774×887 RGBA 图集，每套增加四帧步行、两帧坐姿、两帧发言，坐标见同名 JSON。不同姿态保留原版 64px 基准的整数采样，再统一以 5:4 最近邻放大并在加载时缓存，场景高度上限约 80px，像素尺寸最多有约 1px 舍入。方向在 Tk 中镜像，图片源文件不改写；列表头像仍按 38px 基准采样。
- 场景人物的阴影、姓名牌、回应与照护手势、坐下起立位移和素材缺失时的轮廓同步按 1.25 倍绘制；脚底、过道路线、座位与照护站位坐标固定，命中尺寸和会议气泡位置从实际图片派生。
- 伙伴按过道路径连续移动，横向约 165px/s、入座纵向约 55px/s；目标变化从当前位置重规划，2 秒状态刷新不会重置未完成的动作。
- 到位后用约 0.4 秒的坐下过渡，双方就座后开始交流动画，每 5 秒交换发言者并留短暂停顿；倾听方眨眼、点头，发言方切换抬手动作和点状气泡。散会有对应起立过渡。轮流发言和白板示意笔迹只是动画，不是实际模型消息或输出内容。
- 未在照护、会议或自主活动中的空闲伙伴每隔约 10–13 秒在活动区小范围散步，真实状态变化更新正常活动目的地。会议、已接纳照护与真实忙碌状态优先于自主生活；生活活动沿现有路线走到书架、咖啡机、绿植或沙发附近，再播放对应动作。点击伙伴打开“小世界”；短句回应需要真实模型决定，双人聊天需要双方选择聊天并在休闲厅共同到位。
- 画卷采用与收放共用的约 33ms 心跳，卡片仍为 280ms；家具保留 280ms 逻辑帧，镜头切换约 0.8 秒。动作按单调时钟推进，过长帧间隔限制位移；折叠详情时暂停画卷心跳，关闭时取消场景时钟与待执行的 idle 绘制。
- 动作图集缺失时回退到待机帧和轻微移动起伏；待机图集也缺失时使用简易像素人形。动画不更改数据源状态。

## 简洁界面与数据有效性

详情区依次展示工作室画卷、团队小记、Codex / Kimi 当前状态卡和可折叠的任务记录。任务记录显示进行中 / 待处理摘要，展开后支持按最新轮次状态筛选、分页、会话跳转与复制；字段及持久化规则见 [04-任务记录](04-任务记录.md)。后台 `thread/list`、线程快照的 60 秒有效性与团队统计继续保留，供 Codex 数据源不兼容时回退。额度读取失败，或超过 60 秒没有新采样，会清除旧额度显示并提示自动重试；伙伴与任务记录快照使用独立数据源与 15 秒有效期。

## 环境视角

场景默认让房间和日常动作占据画面，伙伴不常驻显示姓名牌或状态徽记；点击选中时再显示姓名与状态，模型日常台词使用临时气泡。下方两张伙伴卡仍保留真实状态。小猫同样不提供寻找按钮或全局快捷键。画卷顶栏的环境时间来自本地时钟，任务触发的会议与照护动画继续按原规则运行。

人物“小世界”与小猫面板互斥，`Esc` 优先关闭当前面板。心情页展示生活状态与上次模型心思，小记页每页展示 2 条实际经历；“打个招呼”仅排队模型请求，不保证立即回应。“暂停日常”作用于两个伙伴，撤销未完成自主活动与由伙伴发起的照护，使在途生活答复失效；小猫自己的模型开关仍单独管理。
