# 任务记录

最后更新：2026-10-03

## 用户操作

任务记录位于两张伙伴卡下方，默认收起，只显示近期任务的进行中 / 待处理数量。展开独立于画卷和整个详情区，不触发会议或模型请求。

- 首次展开优先选择“待处理”，其次“进行中”，最后“最近”。用户选择后保存筛选；计数对应近期最多 32 个主任务，不代表整个账户的全部历史任务。
- 三个筛选互斥：近 24 小时明确失败、活动过旧的执行状态，以及明确等待审批 / 输入归入待处理；确认正在执行且没有等待标志的归入进行中；完成、中止、空闲、未加载、其他未知及旧异常归入最近。失败与待确认没有有效更新时间，或距今超过 24 小时时，只回到最近分类，原状态仍保留。
- 屏幕高度不足 1200px 时每页 2 条，否则 3 条；展开区只使用整个组件留出的屏幕空间，空间不足时内部滚动，分页按钮也在滚动内容里。刷新时尽量保持首条可见记录所在页。
- 每条显示标题、状态、项目名、模型、相对更新时间和状态依据。“复制信息”包含完整标题（最多 160 字符）、状态、说明、建议、项目路径、模型、更新时间、会话 ID 和可用的地址，不含聊天正文或模型答复。
- “打开会话”交给 Windows 打开 `codex://threads/<UUID>`；已完成时按钮叫“查看结果”。ID 不是严格 UUID 时禁用；Windows 不接受请求时尝试复制会话地址，剪贴板失败会明确提示。
- Windows 接受请求只代表已请求 Codex 打开任务；组件没有会话导航回执。记录已经不存在时不能自动确认是否跳转成功。

## 来源与状态

`CompanionMonitor.snapshot_with_tasks(threads)` 返回 `{"companions": [...], "tasks": {...}}`。同一后台线程约每 2 秒读取一次最新轮次元数据供伙伴和记录共享，不增加数据库轮询、模型请求或日志正文扫描。原 `snapshot(threads)` 两位伙伴列表接口保持可用。

本地 SQLite 连接为只读，主线程筛选和最新轮次查询沿用伙伴规则；可用时追加读取 `threads.cwd`，没有该列则项目留空。存在 `archived` 列时排除已归档任务。记录包括 `thread_turns.started_at / completed_at` 时间，不用整轮时间推算模型请求耗时，不读取错误正文、用户消息或最终答复。

| 最新轮次 / 备用状态 | 展示 | 分类 |
| --- | --- | --- |
| 本地 `inProgress` 且 15 分钟内有活动 | 执行中 | 进行中 |
| 活动线程明确有 `waitingOnApproval` / `waitingOnUserInput` | 等待审批 / 输入 | 待处理 |
| 本地 `inProgress` 活动超过 15 分钟或时间无效 | 待确认 | 24 小时内待处理，否则最近 |
| 本地 `failed` | 执行失败 | 24 小时内待处理，否则最近 |
| 本地 `completed` | 已完成 | 最近 |
| 本地 `interrupted` | 已中止 | 最近 |
| 备用 `active` / `systemError` | 运行中 / 运行异常 | 进行中 / 24 小时内待处理，否则最近 |
| 备用 `idle` / `notLoaded` | 空闲 / 未加载 | 最近 |
| 其他状态 | 状态未知 | 最近 |

等待标志只接受 `status.type == active` 且 `flags` 为字符串枚举列表。本地来源合并等待标志时，本地最新轮次也必须仍处于新鲜的 active；不能覆盖已结束或过期状态。备用线程的空闲和未加载不代表任务完成，也不会成为“查看结果”。

SQLite 缺失或不兼容时回退最近有效的 app-server 线程列表，超过 60 秒的列表不再传入。有效本地空列表表示没有记录，不回退旧任务。两种来源均排除子代理、按 ID 去重、最多保留 32 条。UI 超过 15 秒没有收到新快照时清除旧任务状态并提示暂不可用。

## 模块和数据约定

- `task_records.build_task_records(records=None, threads=(), now=None)` 返回 `rows`、`source` 和 `counts`。来源枚举 `local / fallback / unavailable`；`records=None` 才回退，有效 `[]` 保持本地来源。
- 每行字段：`id, title, model, project, cwd, status, status_text, label_reason, next_action, updated_at, started_at, ended_at, bucket, openable`；输出时间统一为 Unix 秒。`bucket` 为 `attention / active / recent`，计数按最终保留行统计；等待任务只计入待处理。
- 行排序为待处理、进行中、最近，各组按最近时间在前。输入控制字符、脏类型、非法或明显未来时间被清理或忽略；UUID 只接受完整的带连字符格式。
- `TaskBoard` 负责展开、筛选、分页、屏幕空间限制、复制和跳转。状态变化不控制画卷或角色；Tk 主线程接收快照并更新显示。

## 偏好与隐私

`widget-preferences.json` 继续位于项目上级 `.runtime/`，保存 `tasks_collapsed`（默认 `true`）和 `task_filter`（`attention / active / recent`，缺失或无效时首次展开自动选择）。旧偏好兼容；任务记录元数据不另写历史存档，不上传 GitHub，也不发送到宠物模型。

任务记录只打开对应会话并复制本地元数据，不自动重试、终止任务、处理审批或发送提示词。结果与错误详情由用户在 Codex 中查看。
