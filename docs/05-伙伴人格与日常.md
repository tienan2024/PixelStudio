# 伙伴人格与日常

最后更新：2026-10-04

两位角色在真实任务状态之外拥有生活需求、模型生成的心思和实际经历。日常决定由真实 Kimi `k3-256k` 联合生成；Codex 是角色身份，不表示此功能调用 GPT。已有任务、额度和自动总结会议的数据来源保持原样。

## 个性、需求与记忆

| 角色 | 初始个性 | 初始喜好 |
| --- | --- | --- |
| Codex | 安静细致 | 书、绿植 |
| Kimi | 外向好奇 | 咖啡、聊天、橘子 |

初始个性由 `soul_state.PROFILES` 定义。精力 `energy`、陪伴 `social`、好奇 `curiosity` 均为 0–100；缓慢随时间下降，真实工作会额外消耗精力与好奇。成功的读书、咖啡、休息、聊天和照护活动分别恢复相应需求。单次时间补算最多 120 秒；重启后的离线补算最多 30 分钟，温和恢复精力，无死亡或惩罚。

模型更新 `mood` 和第一人称 `thought`，不会直接改变需求或制造完成记录。各角色保留最近 8 条实际小记和按动作累计的 `preferences` 计数；请求发送其中最近 6 条。计数代表实际完成次数，供模型参考，不会改写初始个性。实际说完的日常话语与共同入座会议是观察小记，不增加完成动作计数。

## 使用方式

- 点击人物打开“小世界”，心情页显示个性、心情、三项需求及上次模型心思的时间。
- “小记”每页显示 2 条实际经历，最多 4 页；“常做”来自已完成活动计数。
- “打个招呼”排队请求。目标忙碌时保留招呼，等目标明确空闲再送给模型；其他空闲伙伴仍可有普通日常决定。模型可以选择暂不说话，不保证回复。
- “暂停日常”作用于两个角色：撤销待执行与未完成生活活动、临时台词及伙伴发起的照护，让在途生活结果失效。已使用的调用次数保留；小猫自己的开关独立。
- 人物与小猫面板互斥，`Esc` 先关闭当前面板；房间导航关闭面板。面板打开期间自动会议不接管镜头。没有新增寻找人物的入口。

## 意图与执行

模型动作白名单为 `stay / read / coffee / water_plant / rest / chat / care_cat / stretch`。仅明确 `idle` 的伙伴可开始生活；会议、已接纳的照护及真实工作状态优先，未知或异常状态不会当作空闲。生活只覆盖场景路线，不修改角色的真实 `state`、`task` 或 `detail`。

| 动作 | 场景执行与完成条件 |
| --- | --- |
| `stay` | 安静待着；有台词时停止散步，到位后停留约 6 秒，实际说完才留观察小记 |
| `read` | Codex 去工作室书架，Kimi 去休闲厅书架；到位持续 12 秒 |
| `coffee` | 到咖啡机旁，持续 7 秒，显示杯子与蒸汽 |
| `water_plant` | 到各自对应绿植旁，持续 5 秒，显示浇水动作 |
| `rest` | 到休闲厅沙发旁入座，持续 20 秒 |
| `stretch` | 在所在房间过道伸展，持续 6 秒 |
| `chat` | 两人都选聊天且台词非空，共同走到休闲厅；双方到位后轮流说话，持续 13 秒才给双方留记 |
| `care_cat` | 交给原小猫照护执行器；仅成功 `apply_care()` 后增加照护记忆和计数 |

到位与持续活动均由现有约 33ms 场景心跳推进，单帧计时最多 0.12 秒。折叠详情或长帧间隔不会直接完成活动。未开始的决定最多等待 180 秒，开始后的生活路线也最多保留 180 秒；到期或被抢占不记为完成。任一聊天伙伴被抢占，会清理双方聊天、路线和气泡。重启只恢复显示数据，不重放旧决定。

`care_cat` 的照护动作只允许 `feed / water / play / pet`，两人不能同时选择。小猫思考暂停、忙碌、有用户意图或已有照护时不接纳伙伴意图。接纳计划标记 `source=companion-model`，不覆盖小猫自己的模型心思；到位、计时、冷却和 180 秒过期沿用 [小猫与模型照护](03-小猫与模型照护.md)。

## 请求契约与调用边界

通过 `PIXELSTUDIO_GATEWAY_URL` 指向的 HTTP 回环网关 `/v1/responses` 请求，仅接受 `127.0.0.1 / localhost / ::1`。不发送认证头，不使用环境代理、DNS 或重定向；`localhost` 以 IPv6/IPv4 数字回环候选连接，共用总期限，POST 只发送一次。

只发送以下白名单：本地时段、排队招呼目标、会议标志；两人的 ID、已知真实状态、三项生活需求、个性与喜好、已有模型心思、最近实际小记和完成计数；小猫四项需求、需求提示、照护是否待执行及思考开关。不发送任务标题、真实用户消息、工具输出、额度数据或凭据。模型无工具或系统操作权限。

响应严格为 `companions` 列表，恰好 Codex/Kimi 各一项，每项精确包含以下字段：

```json
{
  "companions": [
    {"id":"codex","mood":"steady","thought":"我想安静地等手头工作结束。","action":"stay","say":"","care":null},
    {"id":"kimi","mood":"cheerful","thought":"我想去喝一杯咖啡。","action":"coffee","say":"先来杯咖啡吧。","care":null}
  ]
}
```

`mood` 只允许 `steady / curious / warm / tired / focused / cheerful`。心思以“我”开头、含中文、最多 60 字；台词为空或含中文且最多 40 字。禁止控制字符。仅 `care_cat` 可有非空 `care`，且值必须是照护枚举。忙碌、未知、异常或会议中的角色必须 `stay` 且台词为空；不符合结构或上下文的整份答复被拒绝，显示错误，不用规则生成替代心思。传输与 Responses/SSE 提取复用 `pet_brain._response(raw, validator=...)`；小猫默认校验器保持原样。

- 常规请求约每 15 分钟一次；排队招呼也遵守至少 90 秒间隔。
- 两个角色共用一套滑动一小时最多 4 次的预算，失败也计数，发送前原子保存；保存预算失败则暂停，不发请求。
- 只有一个在途请求，暂停再恢复也要等旧请求结束；generation 丢弃旧返回，不返还次数。保存返回决定失败也不会把它交给场景执行。
- 45 秒总期限覆盖连接、发送、响应头及正文，计时器可关闭登记的 socket；响应最多 1 MiB，无内部请求重试。
- 小猫自己的 6 次/小时预算独立，理论合计最多 10 次/小时；这是功能调用上限，不是账户剩余额度。伙伴选择照护不额外调用小猫模型。

## 模块与持久化

| 模块 | 职责 |
| --- | --- |
| `soul_state.py` | 需求、个性快照、心思、实际记忆与完成计数；`apply_thought`、`remember`、`complete` 分开 |
| `soul_brain.py` | 联合请求、输入白名单、严格答复校验、预算、暂停与单在途控制 |
| `scene_soul.py` | 请求调度、意图队列、到位连续计时、双人聊天、照护观察及人物面板 |
| `scene_actors.py` | `begin_life / end_life / life_ready / say` 生活覆盖层与像素动作 |

文件保存在项目上级 `.runtime/`，均为版本 1，读写上限 64 KiB、同目录临时文件原子替换：

- `widget-soul-state.json`：`characters` 保存两人需求、心情、心思、时间、上次完成动作、小记与计数，另有 `last_saved_at`。通常每 30 秒保存，关闭时强制保存。损坏时恢复默认人格并显示错误。
- `widget-soul-brain.json`：保存 `enabled / attempts / last_attempt / last_decision`；最后决定另带 `source=model / model / decided_at`。限额坏档暂停思考并保守占满本小时预算；未来时间戳不放宽预算。

`PixelWorld(pet_live=False)` 同时使宠物与伙伴生活处于内存预览，不请求模型、不读写上述存档；桌面入口显式启用真实模式。人物继续采用原来的 1.25 倍比例和图元复用，不新增动画时钟。
